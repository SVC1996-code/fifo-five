# 验收清单与边界测试

下列是要求实现的测试，不是已经通过的项目测试。附件中的三个棋谱样例另用小型独立 Python 检查器验证过，检查结果见 fixture-validation.json；这不等于游戏项目已实现或已验收。

## 规则测试

验证全部四个连线方向、边界与断线，超过目标长度也算胜；横行不能跨行首尾误连。验证未满上限不删除，满上限后每次只删除本方队首，对方队列不变，删除后数量不超过 K，所有棋子不重叠且都在棋盘内。

必须验证不能在落子前被旧棋占据的格子下新棋；新棋暂时构成五连、删旧棋后只剩四连不赢；删掉不在连线上的旧棋而五连仍在才赢；删除不会影响对方棋的位置。终局后禁止额外行动，非法行动不修改状态、历史或队列。

fixtures/rule-cases.json 使用零起始行列和完整开局落子序列。通过同一 core 引擎重放前十二手，再检查后续断言。不得仅加载人工棋盘绕过合法历史验证。

- false-five-after-expiry：X 看似补齐五连，但该线最老棋同时消失，最终不能赢。
- expiry-lock：X 最老棋挡住 O 的四枚持久棋。枚举 X 的全部 24 个合法落点，X 均不能立即赢；行动后 O 均可在 (2,2) 获胜。这证明的只是这一具体局面的一步强制战术，不是从空盘的全局必胜。
- expiry-lock-counterexample：把 O 的最老棋改为那四枚之一；X 在 (0,1) 行动后，O 在 (2,2) 补棋时其自身老棋消失，不能五连。不要把这种情况误报成到期必杀。

## 重复局面与历史

相同占位、不同队列顺序，局面键必须不同。相同配置、相同相对队列和行动方，即使绝对手数与棋子 ID 不同，重复键也应相同。同样队列但行动方不同，也不是同一局面。

测试一次和两次出现不和棋，第三次出现和棋；初始局面计数正确，落子中间态不计数。悔棋后计数恢复，重新开始不沿用旧历史；导出再导入重建相同上下文。构造相同当前局面但历史计数不同的两个搜索输入，验证不能错误复用终局/和棋分值。开启规则步数上限时，还须区分剩余步数。

对小棋盘自动生成合法对局或编写有效循环棋谱，检查重复规则；不要用回合数一直递增导致键永不重复的实现“通过”假测试。

## AI 与终局

所有 AI 在合法非终局返回合法着法。至少战术及搜索 AI 能找到一手胜；有安全回复时不得放任对方下一手直接获胜。验证老棋删除造成的新空位，以及对方补棋也会删除自身棋子的情况。搜索超时/节点耗尽须安全返回，不能把不完整迭代结果当作完成深度。

经典 3×3 永久棋模式可用一个独立全宽穷举器作为小规模正确性参考：初始位置的完美博弈分值应为和棋。不要因此把限时 AI 或 FIFO 默认模式标为不可战胜。小状态/小深度用朴素全宽搜索交叉核验 Alpha-Beta 返回值，覆盖有重复历史的输入。

## UI 与异步

浏览器完成一盘同机游戏和一盘人机游戏；AI 先手可自动开始。AI 思考时重开、悔棋、换规则以及导入另一棋谱，旧任务不能往新对局落子。回放不触发新 AI 行动。

队列未满时不得标注“下一手删除”；队列满时只标注正确最老棋。移动端布局不横向溢出，键盘可以选格落子，终局后不接受落子。颜色之外有 X/O 或其他形状区分。

人机悔棋检查 AI 尚未行动、AI 已行动、玩家刚胜、AI 刚胜、AI 执先但玩家未落子这五种情况。重建对局应同时恢复棋龄、轮次、重复计数和结束状态，而不是只擦除格子。

## 工程交付

真实运行依赖安装、单元测试、类型检查、lint 和构建，记录命令、退出结果和未验证项。测试不应依赖联网服务，默认批量脚本不触发无限任务。导入损坏/过大棋谱、非法配置和版本不支持均须给出明确错误。

实验脚本以真实终局与截止结果分类汇总，并保存每局可重放棋谱。任何基准表格须链接到本项目实际生成的结果文件。附件验证器只证明样例断言，不能充当游戏引擎、完整 AI 或性能测试结果。
